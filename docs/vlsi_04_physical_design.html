4.2 — Floorplanning Industry Core

Fig 4.2 — Floorplan: die area, I/O pad ring, power (VDD/VSS) ring and stripes, macro placement with keepout halos, and standard cell rows filling the remaining core area. Utilization target is typically 60–80%.

Key concepts

  • Core area = cell area / target utilization; aspect ratio = height/width
  • I/O planning: pad placement, bus ordering, differential pair and analog isolation constraints
  • Power planning: VDD/VSS rings + stripes, IR drop must stay < ~10% of VDD, decoupling caps filter supply noise
  • Well ties / substrate contacts prevent latch-up
  • Macro placement (hard macros like SRAM) happens first, with a halo/keepout and routing channel reserved around them

4.3 — Placement

  • Global placement: simulated annealing, force-directed, min-cut partitioning, or modern analytical (quadratic wirelength) placement
  • Legalization: snap cells to the site grid, resolve overlaps, preserve relative ordering
  • Detailed placement: local swaps/shifts to improve timing on critical paths
  • Quality metrics: HPWL (Half-Perimeter Wire Length) as a wirelength proxy, congestion maps, pre-CTS timing estimate
Lab: Run placement in OpenROAD on a small design (RISC-V core or AES). View the placement GUI, identify congestion hotspots, and read the timing report after placement.

4.4 — Clock Tree Synthesis (CTS) NPTEL + Industry

Fig 4.3 — H-Tree: a symmetric binary tree where every leaf sees the same wire length from the clock source — ideal for regular structures like memory arrays. Real SoCs typically use a buffered, non-symmetric clock tree instead, matching delays with inserted buffers rather than geometry.
Setup relaxes with positive skew (δ): T_clk > tCQ + t_comb + t_setup − δ Hold tightens with positive skew: t_hold < tCQ + t_comb + δ (negative skew = hold risk)
CTS structureBest forTradeoff
H-TreeRegular, square dies / memory arraysLow skew, rigid structure
Clock meshLarge designs, irregular flop distributionLow skew but higher power (more metal)
Buffered treeTypical SoC designsMost common; matches delays via inserted buffers

Clock gating: an AND gate (via an Integrated Clock Gating cell, ICG) disables the clock to idle registers, cutting 30–40% of dynamic power in many designs. The enable signal must be stable well before the clock edge to avoid glitches.

4.5 — Routing

LayerTypical use
Metal1 (M1)Local connections, standard cell pins
Metal2–M4Intermediate signal routing
M5–MtopPower grid, long/global signals
  • Global routing: divide the die into routing tiles (GRCs), assign nets to tiles respecting capacity
  • Detailed routing: Lee's maze algorithm (guaranteed path if one exists) or A* (faster, heuristic); track assignment; via minimization
  • DRC in routing: min spacing/width, via enclosure, metal density (for CMP planarity), antenna rules (charge accumulation during plasma etch)
  • Congestion fixes: layer promotion, detour routing, cell spreading; antenna violations fixed with diodes or jumpers to upper metal
Lab: Run the complete flow (Floorplan → Place → CTS → Route → Extract → STA) in OpenROAD on a small design. Fix at least 3 DRC violations manually. Generate GDSII and view it in KLayout (free).

4.6 — Static Timing Analysis (STA) MUST MASTER

Fig 4.4 — The fundamental timing path every STA question is built around: data launched from one flip-flop's Q, through combinational logic, into the next flip-flop's D — checked against the clock period for setup, and against zero delay for hold.
Setup check: Data Arrival Time (AAT) + t_setup ≤ Clock Arrival Time + T_clk Slack(setup) = (T_clk + clk_capture) − (clk_launch + tCQ + t_comb + t_setup) [positive = PASS] Hold check: AAT > Clock Arrival Time + t_hold Slack(hold) = (tCQ_min + t_comb_min) − t_hold [must stay positive — NOT fixable by slowing the clock]
Critical distinction: a setup violation can sometimes be masked by lowering clock frequency. A hold violation cannot — it exists regardless of frequency because it's about data arriving too early relative to the same clock edge. This is one of the most-asked STA interview questions.

Process corners

CornerMeaningWorst for
SS (Slow-Slow)Slow NMOS, slow PMOSSetup
FF (Fast-Fast)Fast NMOS, fast PMOSHold
TT (Typical-Typical)NominalBaseline reference

Higher temperature → slower (mobility drops); lower VDD → slower. On-Chip Variation (OCV) accounts for the fact that cells on the same die still vary — launch path gets a timing credit, capture path a penalty, with CPPR removing double-counted common-path pessimism.
