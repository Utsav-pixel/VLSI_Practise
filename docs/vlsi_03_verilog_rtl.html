Phase 3 — RTL Design & Verification (Verilog / SystemVerilog) The single highest-priority skill for landing an RTL design or verification job. Duration: 8–10 weeks.

Why Verilog, not VHDL: Verilog dominates in India and Asia-Pacific chip design companies (TI, Qualcomm, Intel, Samsung). VHDL is more common in European defense/aerospace. SystemVerilog = Verilog + verification extensions — learn both, starting with plain Verilog.

3.1 — Verilog HDL Fundamentals

Module structure

module module_name (
    input  wire clk,
    input  wire rst_n,
    input  wire [7:0] data_in,
    output reg  [7:0] data_out
);
    wire [7:0] temp;

    // Combinational logic
    assign temp = data_in & 8'hFF;

    // Sequential logic
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            data_out <= 8'h00;
        else
            data_out <= temp;
    end
endmodule

Blocking vs. non-blocking — the rule that matters most

Golden rule: use = (blocking) only in combinational always @(*) blocks. Use <= (non-blocking) only in clocked always @(posedge clk) blocks. Mixing them in the same always block is one of the most common RTL bugs and a guaranteed interview question. 
// Combinational — blocking, use always @(*)
always @(*) begin
    case (sel)
        2'b00: out = a;
        2'b01: out = b;
        default: out = 8'h00;
    endcase
end

// Sequential — non-blocking, use always @(posedge clk)
always @(posedge clk) begin
    if (en) q <= d;
end

Common RTL mistakes

  • Incomplete sensitivity list (mostly a pre-SystemVerilog problem — use always @(*))
  • Unintended latches from incomplete case/if-else (always add a default)
  • Mixing blocking/non-blocking in the same always block
  • Forgetting reset behavior, causing X-propagation issues in simulation

Worked example: Priority encoder

module priority_enc (
    input  [3:0] in,
    output reg [1:0] out,
    output reg valid
);
    always @(*) begin
        valid = 1'b1;
        casex (in)
            4'b1xxx: out = 2'd3;
            4'b01xx: out = 2'd2;
            4'b001x: out = 2'd1;
            4'b0001: out = 2'd0;
            default: begin out = 2'd0; valid = 1'b0; end
        endcase
    end
endmodule

Worked example: Sequence detector FSM ("1011")

Fig 3.2 — State diagram for a "1011" sequence detector. Green edges = din=1, red = din=0. This maps directly onto the case(state) structure in the code below.
module seq_det (
    input  clk, rst, din,
    output reg match
);
    typedef enum logic [1:0] {S0, S1, S2, S3} state_t;
    state_t state, next;

    // State register
    always @(posedge clk or posedge rst)
        state <= rst ? S0 : next;

    // Next state + output logic
    always @(*) begin
        next  = S0;
        match = 0;
        case (state)
            S0: next = din ? S1 : S0;
            S1: next = din ? S1 : S2;
            S2: next = din ? S3 : S0;
            S3: begin
                    match = din ? 1 : 0;
                    next  = din ? S1 : S2;
                end
        endcase
    end
endmodule

3.2 — Testbench Writing & Functional Verification

`timescale 1ns/1ps

module tb_adder;
    reg  [7:0] a, b;
    reg        cin;
    wire [7:0] sum;
    wire       cout;

    adder_8bit dut (
        .a(a), .b(b), .cin(cin),
        .sum(sum), .cout(cout)
    );

    initial begin
        $dumpfile("adder.vcd");
        $dumpvars(0, tb_adder);

        a = 8'h00; b = 8'h00; cin = 0; #10;
        a = 8'hFF; b = 8'h01; cin = 0; #10;
        a = 8'h55; b = 8'hAA; cin = 1; #10;

        repeat(100) begin
            a = $random; b = $random; cin = $random;
            #10;
            if ({cout,sum} !== a + b + cin)
                $error("MISMATCH: a=%0h b=%0h cin=%0b sum=%0h cout=%0b",
                        a, b, cin, sum, cout);
        end

        $display("Test complete");
        $finish;
    end
endmodule

Verification concepts

  • Directed testing vs. random testing vs. constrained-random testing
  • Code coverage: line, branch, condition, toggle, FSM coverage
  • Functional coverage: cover groups, cover points (SystemVerilog)
  • Assertion-based verification (SVA): assert property, assume property

3.3 — RTL to Gates: Logic Synthesis Industry Core

Fig 3.3 — The synthesis flow. Each stage matters: elaboration resolves parameters/generates, technology mapping picks real cells from the target library, optimization then trades off area/timing/power against your constraints (SDC).

SDC constraints (Synopsys Design Constraints)

# Clock definition
create_clock -name clk -period 5.0 [get_ports clk]

# Input/Output delays
set_input_delay  1.0 -clock clk [all_inputs]
set_output_delay 1.0 -clock clk [all_outputs]

# Drive strength and load
set_driving_cell -lib_cell INVX1 [all_inputs]
set_load 0.1 [all_outputs]

# False paths and multicycle paths
set_false_path -from [get_ports rst_n]
set_multicycle_path 2 -from [get_cells slow_block/*]

Reading a synthesis report

  • Critical path — the longest combinational path in the design
  • Slack = Required Arrival Time − Actual Arrival Time. Negative slack = timing violation (tracked as WNS/TNS)
  • Area report — cell count and total area in μm²

Open-source tool: Yosys

yosys -p "
  read_verilog design.v
  synth -top top_module
  write_verilog -noattr synth_out.v
"
